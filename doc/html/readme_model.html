💻 System model

Part of the main README.

The system parameters, either hypothetical or actual, can be tuned by editing the config.cfg file available in the current directory. Machine descriptions are YAML files in machine files. Network descriptions are numeric .cfg tables in network files.

🔌 Cluster model 💭

The resource allocation, intercluster characteristics, and runtime modalities are all included in the cluster model.

Metadata information Description
task_per_node Number of processes placed on one node
number_of_processes Number of simulated processes. Launch the simulator with this count plus one.
number_of_timesteps Number of iterations. collective_mode = 1 forces this to one.
heteregeneous Second system (0: off, 1: primary plus secondary processes). Documented in Heterogeneous mode.
dim_x, dim_y, dim_z Problem size. High-dimensional parameters are ignored for low-dimensional problems.

🔌 Interconnect model 💭

Each network file is one scope (intra-chip, inter-chip, inter-node, or inter-cluster). A row is number_of_simultaneous_process, msg_size_in_bytes, latency_in_ns, inverse_bandwidth, comm_eagerlimit_in_bytes, G_in_ns, comm_o_in_ns, comm_g_in_ns, comm_O_in_ns. config.cfg selects the model with comm_model (0: LogGP, 1: Hockney) and the WaitIO mode with waitio_mode (socket, file, or hybrid).

Column Meaning
latency_in_ns Latency parameter L, in nanoseconds
inverse_bandwidth Inverse bandwidth, GB/s interpreted as bytes per nanosecond
comm_eagerlimit_in_bytes Message size at which the model switches from eager to rendezvous
comm_o_in_ns, comm_g_in_ns, comm_O_in_ns LogGP overhead, gap, and per-byte overhead

P2P_mode is what --help prints. The shipped config.cfg leaves P2P_mode commented out and sets benchmark_kernel to the full header name. heteregeneous, collective_mode, and number_of_timesteps are read by the simulator and are not listed by --help. The spelling compiler-flags in the help text does not match compiler_flags in config.cfg.

👩‍💻 Automating DSEL generation through static analysis

Static analysis is the most reliable for regular communication and known problem sizes. Unstructured or rank-unique patterns need a hand-written DSEL, and some kernels (for example HPCG SpMV) need manual extensions.

To perform the static analysis, the following procedure must be followed before running the DisCostiC batch script:

pip install -r staticanalysis/requirements.txt
cd staticanalysis
python Convert-<benchmark_kernel>.py

Converters in this tree include Convert-HEAT.py, Convert-HPCG.py, Convert-STREAM.py, and Convert-POISSONNS.py.

Files Description
Convert-<benchmark_kernel>.py A helper script that takes the original code and, through annotation, locates code loops and communication and identifies user-defined variables, such as dim_x and dim_y in the Cartesian stencil heat.c code, and ultimately generates DSEL code.
requirements.txt Each (sub)dependency is listed and pinned using "==" to specify a particular package version; see requirements.txt. This project makes use of the lightweight Python tree data structure anytree==2.8.0 and type hints for Python 3.7+ typing_extensions==4.4.0. These dependencies are later installed (normally in a virtual environment) through pip using the pip install -r staticanalysis/requirements.txt command. The generated tree's syntax is the same as the original C/C++ code.

For the specified program, this will produce the following files:

Files Location Description
<benchmark_kernel>.c nodelevel/kernels It comprises only the generated computational loop kernel of the MPI parallel program.
<benchmark_kernel>_<kernel_mode>.hpp test It includes the entire generated code expressed in DisCostiC DSEL language.

📝 Code blueprint as DisCostiC input 💭

The following DSEL code example shows the simplest illustration of how the domain knowledge of the applications is expressed in the DisCostiC language:

DisCostiC::Event recv, send, comp;
for (auto rank : DisCostiC::getRange(systemsize))
{
DisCostiC->Rank_Init(rank);
DisCosTiC->SetNumRanks(systemsize);
/* initialization */
comp = DisCostiC->Exec("LBL:STREAM_TRIAD", recv);
send = DisCostiC->Send(res, 8, MPI_DOUBLE, (rank + 1) % systemsize, MPI_COMM_WORLD, comp);
if(rank != 0)
{
recv = DisCostiC->Recv(res, 8, MPI_DOUBLE, rank - 1, MPI_COMM_WORLD, comp);
}
else
{
recv = DisCostiC->Recv(res, 8, MPI_DOUBLE, systemsize - 1, MPI_COMM_WORLD, comp);
}
DisCostiC->Rank_Finalize();
}

📝 Code documentation: suite of C++ data structures and enumerated types 💭

The HTML and LaTeX documentation can be generated by doxygen. To build the documentation, navigate to the Doxyfile file available in the current directory and run the command:

doxygen Doxyfile

After doxygen Doxyfile, the HTML tree is doc/html/index.html. The generated HTML is committed under doc/html/ and published at https://rrze-hpc.github.io/DisCostiC-Sim/doc/html/index.html. The documentation shipped with this tree is the Markdown guides in doc/.
